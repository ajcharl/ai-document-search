# RAG Document Search

A fully local, free **Retrieval-Augmented Generation** app. Upload PDF or TXT documents, ask questions, and get answers generated by a local LLM (Ollama + Mistral) grounded **only** in the content of your uploaded documents.

## What it does

1. You upload a PDF or TXT.
2. The backend extracts the text, splits it into chunks, embeds each chunk with `all-MiniLM-L6-v2`, and stores them in a persistent ChromaDB collection.
3. You ask a question. The backend embeds the question, retrieves the most similar chunks from ChromaDB, and sends those chunks plus your question to Ollama running Mistral.
4. You get an answer based strictly on the retrieved chunks, plus a list of source snippets used.

## Tech stack

- **Frontend:** React + Vite
- **Backend:** FastAPI (Python)
- **Vector DB:** ChromaDB (persistent, local)
- **Embeddings:** `sentence-transformers/all-MiniLM-L6-v2`
- **LLM:** Ollama running `mistral` (local)
- **PDF parsing:** `pypdf`

No OpenAI, no paid services, nothing leaves your machine.

### Flow

```
[ PDF/TXT ] -> document_loader -> chunker -> embeddings -> ChromaDB
                                                              |
[ question ] -> embeddings ---------------------------------> | top-k chunks
                                                              v
                              prompt = context + question --> Ollama (mistral) --> answer
```

## Setup

### 1. Install Ollama

- Download Ollama from <https://ollama.com/download> and install it.
- Make sure the Ollama service is running (the installer typically starts it as a background service / tray app).

### 2. Pull and run Mistral

```bash
ollama run mistral
```

The first run downloads the model (a few GB). Leave Ollama running. The backend calls it at `http://localhost:11434/api/generate`.

### 3. Backend

```bash
cd backend
python -m venv .venv
# Windows
.venv\Scripts\activate
# macOS/Linux
source .venv/bin/activate

pip install -r requirements.txt
uvicorn main:app --reload --port 8000
```

The backend is now at <http://localhost:8000>. The first embedding call downloads the `all-MiniLM-L6-v2` model (~80 MB) once.

### 4. Frontend

```bash
cd frontend
npm install
npm run dev
```

Open <http://localhost:5173>. The Vite dev server proxies `/upload` and `/ask` to the backend on port 8000.

## API

### `POST /upload`
- multipart/form-data, field `file` — `.pdf` or `.txt`
- Response: `{ "message": "Stored N chunks from <filename>.", "chunks": N }`

### `POST /ask`
- JSON: `{ "question": "..." }`
- Response: `{ "answer": "...", "sources": [{ "source": "<filename>", "snippet": "..." }, ...] }`
- Returns 503 if Ollama is not reachable.

## Example usage

1. Start Ollama (`ollama run mistral`), backend (`uvicorn ...`), and frontend (`npm run dev`).
2. In the UI, upload e.g. `handbook.pdf`. You'll see "Stored 42 chunks from handbook.pdf."
3. Ask: *"What is the company's vacation policy?"*
4. The answer appears, along with the source chunks used to generate it.

If the answer is not in the uploaded documents, the model will say it does not know based on the uploaded documents.

## Troubleshooting

- **"Could not reach Ollama at http://localhost:11434"** — Ollama isn't running. Start it and run `ollama run mistral`.
- **First request is slow** — the embedding model and Mistral are still warming up / downloading.
- **PDF extracted no text** — the PDF is likely scanned images. OCR is not included here; convert to text first.
